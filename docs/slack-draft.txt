[스켈레톤 데모 시나리오 + 코드에서 뽑은 명세 공유]

동작하는 스켈레톤으로 이전 한 건을 화면에서 끝까지 돌리는 순서와, 지금 코드가 실제로 하는 일을 정리한 문서 두 개를 올립니다. 둘 다 AI 초안이고 팀 검토 전입니다.

1) DEMO.md - 데모 순서
- 맥에서 api, worker, web 세 개를 띄우고, 버튼 세 번(명세 확정, 승인, 실행 시작)으로 이전 한 건이 초안에서 완료까지 15칸을 지납니다.
- 사이사이에 비용 추정, 계획서와 승인 지문 검사, 감사 기록, 회사 벽, DB 복제 컷오버를 보여 줍니다.
- 장면마다 보여 줄 화면이나 명령, 성공 기준, 실측 시간을 적었습니다. 화면 캡처 4장 포함.

2) SPEC-FROM-CODE.md - 코드에서 뽑은 명세
- 상태 22개, 갈 수 있는 길 53개, 조건 붙은 길 21개와 멈춤 규칙 2개
- API 10개(/api/v1), 큐 15개 중 처리기 붙은 것 13개, DB 표 9개, 묶음 8개의 책임
- STUB 64곳, 사람이 정할 것(TODO human) 28개 목록

클라우드에서 같은 통합본을 직접 돌린 숫자
- typecheck 오류 0, 단위 테스트 75 통과 / 실패 0, DB 테스트 21/21
- smoke 초안에서 완료까지 7.8~8.2초 (3회)
- 비용 추정 응답 17~25ms. 피크 10rps 기준 GCP 월 $146.9, AWS 월 $227.5, 온프레 월 $250
- DB 컷오버 쓰기 멈춤 중앙값 47ms (43~53, 5회), 그동안 쓰기 3,667건 중 실패 0

같이 봐야 할 빈 곳
- 롤백, 멈춤, 취소 API가 아직 없습니다. 화면에서 되돌리기를 보여 줄 수 없습니다.
- 거절한 이전을 다시 계획하는 경로가 없습니다.
- Idempotency-Key를 경로가 아직 쓰지 않습니다. 같은 키로 두 번 보내면 이전이 두 개 생깁니다.
- DB 복제 모듈은 완성됐지만 워커에 아직 안 붙었습니다. 그래서 데모에서는 따로 보여 줍니다.
- 비용은 화면과 계획서에 아직 없습니다.
- 조건에 막힌 작업이 감사 기록에 안 남습니다.

정해야 할 것 중 데모에 바로 걸리는 것
- 트래픽 판정이 나쁘거나 배포가 실패하면 롤백으로 갈지, 멈춤으로 갈지
- 정리 전에 사람 승인을 받을지

기본 리전은 서울입니다. 어댑터, Terraform, 비용 추정 기본값이 모두 서울로 맞춰져 있습니다.
